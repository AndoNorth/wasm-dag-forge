# Job contract

Owner epic: #5 (DAG configuration schema and validator).
Version: 1
Consumers: dispatch API (#24), workflow (#6), admission (#8), placement (#9), storage (#3), load CLI (#14), failure scenarios (#15) and the system tests (#17).

A job is a JSON document, a template of tasks keyed by id.
This directory pins the document schema, the error table and the vectors, and the code lives in the packages below.
Breakdown and the rationale of every limit: [docs/epics/04-validator.md](../../docs/epics/04-validator.md).

## Files

| File | What it is |
| --- | --- |
| `VERSION` | the contract version, bumped by every contract-change PR |
| [schemas/job/1.0.json](schemas/job/1.0.json) | the JSON Schema of a document, generated from the models |
| [schemas/plan/1.json](schemas/plan/1.json) | the JSON Schema of a compiled plan, generated from the models |
| [schemas/stats/1.json](schemas/stats/1.json) | the JSON Schema of the statistics of a plan, generated from the models |
| `check.sh` | validates one document with the `ci` profile and the live slots files, see Checking a document |
| [errors.yaml](errors.yaml) | every error code with its class and meaning, validated by [errors.schema.json](errors.schema.json) |
| [registry.json](registry.json) | the task type registry and the aggregation registry, generated from `packages/jobdoc/src/wdf_jobdoc/registry.py` |
| [limits.yaml](limits.yaml) | the numbers of the profiles `ci`, `dev`, `soak` and `permissive`, validated by the generated [limits.schema.json](limits.schema.json) |
| `vectors/invalid/schema/<code>/` | documents that the loader refuses, each with the code of its directory name |
| `vectors/slots-fixture/ci.yaml` | a fixed copy of the `ci` slots file, so that tests never change with `deploy/presets/` |

The schemas, the registry and the limits schema are generated by `python -m wdf_jobdoc.schemagen` and checked by `python -m wdf_jobdoc.schemagen --check`, and none is edited by hand.

## The document

The document carries `schema: "urn:wdf:schema:job:1.0"`, optional `parameters` declarations and `max_parallel`, and `tasks` keyed by task id.
A task id follows the pattern of `producer.task` in the artifact contract.
There are exactly three task types, `compile`, `simulate` and `aggregate`, and a field that a type does not have is an error, so a typo is never a silent default.
Each type has a `params` object of its own, and the per-type fields are in the schema.

Documents hold integers, strings, booleans and lists of them, and no floats.
The one decimal is `cpu` in cores with at most three decimal places, read as an exact decimal and kept as integer millicores.
A seed is an integer below 2^53, so no JSON reader rounds one.

A placeholder is the closed one-key object `{"param": "<name>"}`.
It stands only as the whole value of an `args` key of a simulate or aggregate task, or as the `seed` of a simulate task, and never reaches a compile task.
Substitution replaces that one value and never concatenates, computes or branches.

## Packages

| Package | Import | Holds |
| --- | --- | --- |
| `packages/jobdoc/` | `wdf_jobdoc` | the document, plan and statistics models, the strict loader, the registries and the limits profiles |
| `packages/jobcheck/` | `wdf_jobcheck` | `validate`, every pass over a document as one report |
| `packages/plan/` | `wdf_plan` | `compile_plan` and `bind`, and the `Plan` and `PlanStats` models re-exported |
| `packages/jobpatch/` | `wdf_jobpatch` | `patch_check`, the compatibility of a changed plan of a paused job |
| `packages/jobexamples/` | `wdf_jobexamples` | the example documents, the parameter vectors and the generator |
| `packages/jobtools/` | `wdf_jobtools` | `python -m wdf_jobtools {validate,plan,patch-check}` |

Entry points that no lane has implemented yet raise `NotImplementedError` with `not implemented: owned by lane <letter>`, and the command line exits 3 with the same text.
The plan and statistics models live in `wdf_jobdoc` next to the schema generator, so that one module generates every schema and the packages stay acyclic.
The libraries of `jobdoc`, `jobcheck`, `plan` and `jobpatch` import no file system, clock, randomness, logging or event module and call neither `open` nor `print`, and `packages/jobdoc/tests/test_purity.py` keeps that true.
The only exempt modules are the profile file reader, the schema generator and the `check` command.

## Checking a document

`check.sh <document.json>` exits 0 when the document is valid, 1 with one `reason: <code>: <detail>` line per issue on stderr, and 2 on a usage error.
It exits 3 while a pass is still a stub.

## Registries

A task type fixes the pool of its tasks, so the document never names a pool, the kinds of in-job input it accepts with their count, and the outputs it declares.
`aggregate` names one aggregation of the registry and the arguments that aggregation takes, and the document schema refuses an aggregation or an argument outside it.
The compile source bundle is `params.source` and never an entry of `inputs`, which holds only logical references between tasks of the job.

## Limits profiles

`load_profile(preset, root, slots_dir=None)` returns the numbers of a profile with the pool table of its slots file, read as millicores and MiB from the limits of the compile, simulate and aggregate pools.
A slots file without one of the three pools raises `SlotsIncomplete` naming it, and no stand-in budget exists.
`dev` and `soak` use the `ci` numbers and read their own slots file, and `permissive` lifts the numbers about a hundredfold, sets ceilings that replace the slot of every pool, and reads the `ci` slots.
`max_job_duration_days` of `ci` equals `MAX_JOB_DURATION_DAYS` of `wdf_compat.window`, and a test keeps them equal.

## Loader

`wdf_jobdoc.parse_document(data, max_bytes)` returns a `Document` or raises `DocumentInvalid`, which carries `issues`, each an `Issue(code, path, message)` with a JSON Pointer `path`.
It refuses these before the models run, and no input ends in a traceback:

- bytes over `max_bytes`, checked before parsing
- anything that is not UTF-8 JSON, including a byte order mark, UTF-16, nesting beyond the parser and integers beyond Python's digit limit
- duplicate keys, `NaN` and the infinities, and a decimal number anywhere but `cpu`
- strings and keys that are not in Unicode normalization form NFC or that hold a lone surrogate

A document whose `schema` is a version the reader does not know is refused, and a minor above the reader's own is refused too, because a submitted document is not replayed after a deploy as an event is.
Issues are sorted by path then code and capped at 100.

## Error classes

Every code is in [errors.yaml](errors.yaml), in one of eight classes that name the pass that reports it:

| Class | Pass |
| --- | --- |
| `schema` | the loader and the document models |
| `graph` | dependencies and cycles |
| `reference` | inputs, outputs and placeholders against the registry |
| `bundle` | what the caller's resolver returns for a source bundle or an index object |
| `resource` | the slot budget of each pool |
| `limit` | the limits profile |
| `params` | the per-job values of a batch |
| `patch` | a changed plan of a paused job |

A code is also the name of the directory that holds its fixtures under `vectors/`.

## Vectors and the loader test

`vectors/invalid/schema/<code>/*.json` must fail with that code as the first issue.
`packages/jobdoc/tests/test_vectors.py` runs them through `parse_document` with the `ci` document limit read from `limits.yaml`.

## Changing it

A change after the pin is a `contract-change` PR with a consumer list and a bump of `VERSION`.
A change to a generated schema touches `contracts/`, the model under `packages/` and the regenerated file together, because the drift check fails otherwise.
